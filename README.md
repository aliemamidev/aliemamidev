## Currently building: Rouhi

<div align="center">

### [Rouhi · rouhi.ir](https://rouhi.ir)

</div>

I am currently working on **Rouhi**, a production-grade food-ordering and organization operations platform. The product is private and not represented by a public source repository, but its public website is available at [rouhi.ir](https://rouhi.ir).

The platform includes:

- A customer-facing food catalog and service-day ordering experience
- Organization-based ordering with canonical restaurant-facing orders
- Organization members, units, addresses, policies, reports, and administration
- Organization wallet, finance workflows, deposits, settlement, and official invoices
- Order review, approval, kitchen, delivery, proforma, and invoice flows
- OTP authentication, revocable sessions, secure cookies, CSRF protection, throttling, and validation
- Role-based access control, permission-aware navigation, access review, and support impersonation
- Audit logging and investigation workflows across authentication, orders, finance, SMS, and operations
- PDF generation, document delivery, SMS notification workflows, and payment gateway integration
- Demo isolation, health checks, production guards, Docker deployment, and Nginx routing

## Engineering principles

### Build for the real workflow

The best software is not the one with the most features. It is the one that makes the important workflow obvious, safe and repeatable.

### Keep sensitive data protected

Authentication state, private files, financial data, session lifecycle, audit trails and organization boundaries deserve explicit design — not accidental security.

### Prefer clear systems over clever systems

Shared primitives, centralized API behavior, typed contracts, focused tests and useful documentation make a product easier to evolve.

### Respect the edge cases

Multilingual text, RTL layouts, historical prices, money units, permissions, session transitions, mobile screens and partial failures all matter in production.
